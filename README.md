# WinRust

Переписанные на Rust системные компоненты Windows 10/11: Проводник, Диспетчер задач,
менеджер служб, системные утилиты и ядро (библиотека доступа к Win32). Цель — не демо,
а повседневный рабочий инструмент: каждое окно делает то же, что делает оригинал.

Всё собирается в один workspace, без сторонних бинарников: только `windows-sys` для
FFI и `eframe/egui` для интерфейса.

## Что уже работает

| Компонент | Файл | Возможности |
|---|---|---|
| **Проводник** | `winrust-explorer.exe` | Интерфейс как в Windows 11: вкладки, командная панель (New / Cut / Copy / Paste / Rename / Delete / Share), хлебные крошки, поиск по подпапкам, **множественный выбор** (Ctrl/Shift), **перетаскивание файлов** на папки, четыре режима вида (таблица, список, крупные значки, содержимое), панель предпросмотра с текстом, боковая панель (Быстрый доступ, диски с занятым местом, папки), иконки 16/32/48 px из системного списка образов, локализованный тип файла, размеры/даты как в Explorer, операции копирования/перемещения в фоне с прогрессом и отменой, контекстные меню с «Открыть с помощью», «Запуск от имени администратора», «Отправить», «Извлечь», корзина и безвозвратное удаление, «Копировать как путь» |
| **Диспетчер задач** | `winrust-taskmgr.exe` | Процессы с CPU% (реальное семплирование), памятью, **диском** и **сетью** по PID, группировка по приложению, сортировка по любой колонке, завершение/приостановка/возобновление, приоритет, «Открыть расположение файла», «Свойства», вкладки Производительность (графики CPU/память/ядро), Автозагрузка (с реальным включением/отключением через `StartupApproved`), Пользователи, Сеть (TCP/UDP-соединения), Службы |
| **Службы** | `winrust-services.exe` | Полный список Win32-служб и драйверов, фильтр, состояние, тип запуска (в т.ч. отложенный автозапуск), путь к исполняемому файлу, учётная запись, зависимости, **редактирование описания**, старт/стоп/пауза/возобновление, диалог свойств, точные ошибки Win32 при отсутствии прав |
| **Системные утилиты** | `winrust-sysctl.exe` | Обзор системы (ОС, CPU, RAM, uptime), переменные среды с редактированием и `WM_SETTINGCHANGE`, автозагрузка, схемы электропитания с переключением, сеть, ядро/версии, драйверы, отчёт о поддержке (диагностика) |
| **Ядро (lib)** | `winrust-core` | Безопасные RAII-обёртки над Win32: процессы, службы, файловая система, реестр, сеть, оболочка, иконки, пользователь/токен, системные `Zw`-запросы, широкие строки, коды ошибок |
| **Драйвер (KMDF)** | `WinRustKernel.sys` + `winrust-driver.exe` | Настоящий kernel-mode драйвер на Rust: таблица процессов из `ZwQuerySystemInformation` (видит и защищённые PPL-процессы, к которым `OpenProcess` не пускает), загруженные драйверы с базовыми адресами из `SystemModuleInformation`, агрегатные счётчики, блокировка запуска процессов через `PsSetCreateProcessNotifyRoutineEx` — список только в RAM, снимается выгрузкой |
| **Лаунчер и установщик** | `WinRust.exe` | Единое окно: запуск компонентов, **выборочная замена системных программ** (галочка на каждый компонент), **точка восстановления и файловый бэкап перед изменениями**, просмотр и откат бэкапов, журнал действий |
| **Рабочий стол** | `winrust-desktop.exe` | Полноценная оболочка вместо `explorer.exe`: значки рабочего стола (сетка с сохранением позиций в `%APPDATA%\WinRust\desktop.json`, перетаскивание с привязкой к сетке, контекстное меню, двойной щелчок), панель задач (Пуск, закреплённые компоненты, запущенные окна с переходом по PID, CPU/RAM, часы), меню Пуск (поиск по установленным программам, известные папки, питание, «Вернуться к оболочке Windows»). Ставится в автозапуск оболочки через `Winlogon\Shell`, снимается той же кнопкой или удалением в лаунчере |

## Замена системных программ

`WinRust.exe` — не просто список кнопок: он ставит отдельные компоненты на место
системных, выборочно и обратимо.

| Уровень интеграции | Что делает | Права | Откат |
|---|---|---|---|
| **Portable** | ничего не меняет, программа запускается из своей папки | обычные | не требуется |
| **Redirect (IFEO)** | `HKLM\...\Image File Execution Options\<exe>` → `Debugger`; Windows запускает сборку WinRust вместо оригинала | администратор | удаление одного значения |
| **Replace** | бэкап оригинала → подмена системного файла; если файл занят, замена планируется на следующую перезагрузку (`MoveFileExW` + `MOVEFILE_DELAY_UNTIL_REBOOT`) | администратор | возврат файла из бэкапа |
| **Custom shell** | `Winlogon\Shell` → WinRust Explorer как оболочка входа в систему | администратор | удаление значения |

Перед любым изменением предлагаются две независимые страховки, включённые по умолчанию:

* **Точка восстановления** — `SRSetRestorePointW` (`MODIFY_SETTINGS`), тот же механизм,
  что «Создать точку восстановления» в Панели управления, поэтому откатиться можно
  средствами самой Windows.
* **Файловый бэкап** — точные копии заменяемых бинарников в
  `%ProgramData%\WinRust\backup\<timestamp>\` вместе с `session.json`; в лаунчере есть
  список сессий и восстановление в один клик. Отсутствовавшие ранее файлы при откате
  удаляются.

Что уже установлено, лаунчер помнит в `HKLM\SOFTWARE\WinRust\Installed`, поэтому кнопка
«Restore» работает и через неделю после установки. Все действия пишутся в журнал окна.

## Драйвер ядра

Реализован в `crates/winrust-kernel` (KMDF 1.33, `wdk` 0.5 / `wdk-sys` 0.5 / `wdk-build` 0.6)
и собирается отдельным workflow `.github/workflows/kernel.yml`, потому что требует WDK и
libclang.

```
winrust-driver status           # зарегистрирован ли, доступен ли, версия протокола
winrust-driver install <sys>    # скопировать .sys, создать службу, запустить
winrust-driver processes 40     # процессы глазами ядра (включая PPL)
winrust-driver modules 30       # драйверы: базовый адрес, размер, имя
winrust-driver block <name.exe> # запретить запуск образа (только в RAM)
winrust-driver remove           # остановить, удалить службу, удалить образ
```

Устройство `\\.\WinRust` принимает только `METHOD_BUFFERED` IOCTL — ядро никогда не
разыменовывает пользовательский указатель. Протокол вынесен в `crates/winrust-kernel-abi`
(`#[repr(C)]`, общий крейт для ядра и клиента), поэтому стороны не могут разъехаться.

Для машины, где драйверы ставятся через PnPUtil, есть `WinRustKernel.inx`. Подпись:
CI собирает **test-signed** образ; для обычного запуска на своей машине нужно
включить тестовый режим загрузки (`bcdedit /set testsigning on`) и перезагрузиться.

## Сборка

Нужен Rust 1.75+ и Windows 10/11 (x64). Кросс-компиляция не поддерживается — используются
нативные API.

```powershell
cargo build --release
# бинарники появятся в target\release\
```

Запуск конкретного компонента:

```powershell
.\target\release\WinRust.exe              # лаунчер
.\target\release\winrust-explorer.exe
.\target\release\winrust-taskmgr.exe
.\target\release\winrust-services.exe
.\target\release\winrust-sysctl.exe
.\target\release\winrust-desktop.exe      # оболочка рабочего стола
```

Для действий, требующих прав администратора (запуск/остановка служб, изменение чужих
процессов), запускайте соответствующий .exe от имени администратора.

## Технические заметки

* **Никаких unsafe-утечек в UI.** Весь `unsafe` сосредоточен в `winrust-core`; каждый
  хэндл закрывается через RAII, включая `HKEY` (через `RegCloseKey`).
* **CPU%** считается по дельте `GetProcessTimes` между снимками, а не по загрузке системы —
  так же, как это делает настоящий Диспетчер задач.
* **Диск по процессу** — из `GetProcessIoCounters` (`ReadTransferCount + WriteTransferCount`).
* **Сеть по процессу** — из extended TCP statistics (`Set/GetPerTcpConnectionEStats`,
  `TCP_ESTATS_DATA_ROD_v0`), агрегированная по PID.
* **Автозагрузка** — чтение `…\CurrentVersion\Run` плюс `StartupApproved\Run` (12-байтовый
  блоб: `0x02` включено, `0x03` отключено), редактирование через `RegSetValueExW`.
* **Версия/издатель файлов** — `GetFileVersionInfoW` + `VerQueryValueW` (`VS_FIXEDFILEINFO`).
* **Даты изменения файлов** — собственный `civil_from_days` (алгоритм Ховарда Хиннанта),
  потому что `FileTimeToSystemTime` отсутствует в windows-sys 0.59.
* **Быстрый листинг** — `FindFirstFileExW` с `FindExInfoBasic` + `FIND_FIRST_EX_LARGE_FETCH`
  (как сам Explorer): на папках в десятки тысяч файлов это в 2–4 раза быстрее, чем
  `FindFirstFileW`. Сортировка — decorate-sort-undecorate по индексам, без клонирования строк.
* **Крупные значки** — `IImageList::GetIcon` через `SHGetImageList` (32/48/256 px); vtable
  объявлена вручную, т.к. `IImageList` отсутствует в windows-sys 0.59.
* **Буфер обмена** — Win32 `CF_UNICODETEXT` (копирование пути работает во всех приложениях).
* **Пакованные структуры Win32** (`RESTOREPOINTINFOW`, `STATEMGRSTATUS` — `#[repr(packed)]`)
  заполняются и читаются через невыровненные указатели (`addr_of_mut!` +
  `copy_nonoverlapping` / `read_unaligned`); обычная ссылка на поле — это E0793 и UB.

## CI

`.github/workflows/build.yml` на каждый пуш собирает fmt/test/build/clippy/release на
`windows-latest` и коммитит результаты в `docs/ci/build/*.txt` — это единственный способ
увидеть вывод сборки в средах без локального toolchain.

`.github/workflows/kernel.yml` собирает драйвер с WDK из NuGet-пакетов
(`Microsoft.Windows.WDK.x64` + `Microsoft.Windows.SDK.CPP`) и `+crt-static`,
как это делает собственный CI `microsoft/windows-drivers-rs`.

`.github/workflows/fmt.yml` — канонический форматтер: прогоняет `cargo fmt --all` на
`windows-latest` и коммитит результат обратно в ветку, так что `cargo fmt --check` в
build.yml остаётся чистым без локального rustfmt.
